## 團隊背景 (About the Team)

Billing 團隊負責重構企業處理 `定價 (pricing)`, `帳單 (billing)` 與 `發票 (invoicing)` 的方式,
目標是打造可規模化且透明的次世代帳務平台, 對內支撐 Airwallex 成長, 對外作為客戶可直接整合的產品.
工程團隊橫跨 `上海與新加坡`, 需與 GTPN, PA, Scale, Issuing, Spend 等領域協作,
將端到端的定價與計費流程自動化.

## 崗位職責 (Responsibilities)

- 主導 Airwallex 工程系統的規劃, 設計與實作.
- 與業務及產品團隊深入理解商業需求與場景, 完成系統分析, 架構設計與核心功能開發, 掌握複雜系統設計以確保架構品質.
- 基於公司微服務框架設計並開發元件.
- 為團隊引入創新技術與方案.
- 負責技術團隊的建設與管理, 建立良好的內部編碼規範.

## 我的對位敘事 (Positioning Angle)

不要在 Java 年資上硬碰. 改以 `平台工程 (platform engineering)` 對位:
JD 真正要的是能在高併發下把複雜系統設計對的人, 而 Java 只是載體.
用 ByteDance 的跨資料中心一致性與冗餘設計對應帳務平台的正確性需求,
用 TSMC 的 30 行函式與 90% 覆蓋率對應 JD 的 "建立內部編碼規範",
用 Change Healthcare 的 Spring Boot Batch 與 EventBus 框架證明 Java 生態的實作深度而非年份.

支付領域缺口用三個概念補足即可過關: `複式簿記 (double-entry ledger)`, `冪等性 (idempotency)`,
`對帳 (reconciliation)`. 面試時能畫出 billing 的 rating 到 invoicing 到 settlement 資料流, 即可抵銷年資問題.

`注意`: 此 JD 明顯是 HR 沿用的舊版 Java 通用模板 (Java 8, Docker Swarm, Aliyun, AngularJS 世代),
與 About the team 所述的次世代平台不一致. 不要照著這份 JD 準備技術面, 應以團隊實際棧為準.
