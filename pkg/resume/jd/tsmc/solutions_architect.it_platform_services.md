## 崗位職責 (Responsibilities)

- `方案設計與架構`: 整合雲端基礎設施在內的多種 IT 平台服務, 設計可靠且可擴充的 IT 系統架構; 與開發及維運團隊緊密協作, 確保方案符合技術需求並能支撐業務目標.
- `技術評估與建議`: 持續評估並推薦 compute, storage, database, security, networking, application 與 AI/ML 框架等領域的 open-source 技術, 以強化 IT 平台服務.
- `跨部門協作`: 與 IT DevOps 團隊共同交付滿足 TSMC 可靠性與可擴充性需求的 workload solution.
- `產品規劃與執行`: 與 IT Product Manager 協同管理 IT 託管平台產品的生命週期.
- `文件與報告`: 建立並維護 workload reference architecture 文件; 定期向高階主管彙報產品績效, 專案進度與平台服務採用率.

`硬性要求 (Must-have)` — 原文 `Job Qualifications`:

- `學歷`: 資工, 資訊科技, 資管或工程相關`碩士`學位.
- `10 年以上`為 enterprise, AI/ML 與製造工作負載設計複雜解決方案架構的經驗, 含與 DevOps 及工程團隊協作進行 IT/產品開發與交付.

## 我的對位敘事 (Positioning Angle)

`與 IT DevOps Manager 一檔可同時投遞`: 兩者同屬 IT 組織但職涯軌道不同 (architect 與 manager), JD 本身也明言兩個角色要互相協作, 因此同時開兩條線不會互相排擠, 反而讓對方 HR 看到彈性.

`敘事主軸`: JD 要的是`能把平台服務組裝成可靠工作負載的人`, 不是元件專家. 履歷最強的證據是 ByteDance 那段 — 把內外部服務對齊到新資料中心, 並設計全球資料中心備援, 讓實作與維護成本降了 2 個 job grade. 這是「架構決策換取營運成本」的完整故事, 正好對應 well-architected 的取捨語言.

`要補的`: 產品化語彙. 把過去的平台工作重述為 roadmap, adoption rate 與 lifecycle 三段, 並準備一份「如果我接手 TSMC 的 IT platform product, 前 90 天我會怎麼盤點採用率」的答案.

`要處理的`: 2022 年在 TSMC 任職 5 個月的紀錄, 說明方式同 IT DevOps Manager 一檔.
